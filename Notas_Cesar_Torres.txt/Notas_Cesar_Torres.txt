Primeros pasos para correr el proyecto

Ya con el proyecto en mi computadora, cree el entorno virtual, que entiendo que es para no afectar toda la 
Configuración de la computadora y es como para tener un sandbox solo del proyecto con sus parametros:

python3 -m venv .venv

Luego lo active:

source .venv/bin/activate

Después instale los requerimientos que venían en el proyecto del profesor.
Aquí fue donde empece a toparme con varios errores, porque el proyecto estaba
mas pensado para Windows y yo lo estaba corriendo en una Mac mini.

Algunos módulos de audio no estaban instalados o no funcionaban igual en Mac.
Tuve que investigar como instalar los paquetes que hacían falta para macOS.
Después de eso ya pude seguir avanzando.


Entendiendo el proyecto

Me tarde varios días revisando los archivos para entender que hacia cada uno.
Al principio se via medio confuso porque hay varios archivos, pero ya después
entendi que esta separado por responsabilidades.

Los archivos principales que fui entendiendo fueron:

Asistente_Voz_IA.py
Este es el archivo principal. Es el que arranca el asistente.

asistente_voz/agente.py
Este es como el cerebro del asistente. Recibe el texto que se extendió por voz,
revisa que comando es, identifica el verbo y manda llamar la acción que toca.

asistente_voz/config.py
Aquí están las palabras de activación, los verbos permitidos, el micrófono y
las rutas de las aplicaciones. Aquí agregue palabras como jarvis, jarviz, dime,
dame y donde.

asistente_voz/gramatica.py
Aquí esta la gramática del asistente. Es la que valida si la frase que dije
tiene una estructura correcta. Por ejemplo:

jarvis dame el tipo de cambio

El asistente primero valida que exista una palabra de activación, luego un verbo
y después el objeto o la consulta.

asistente_voz/acciones.py
Aquí es donde están las funciones que hacen el trabajo real, por ejemplo abrir
una aplicación, buscar en Google, reproducir en Youtube, consultar Banxico,
consultar la IP publica o consultar el clima.

asistente_voz/voz_stt.py
Este archivo es el oido del asistente. STT significa Speech To Text, o sea voz
a texto. Usa el micrófono, escucha lo que digo y con Google convierte mi voz a
texto.

asistente_voz/voz_tts.py
Este archivo es la boca del asistente. TTS significa Text To Speech, o sea texto
a voz. Recibe una frase de texto y la convierte en audio para que la computadora
me conteste hablando.

Problema con Mac y la voz

Cuando intente correr el proyecto como venia del profesor, no funciono bien en
mi Mac. Una parte importante fue que el proyecto usaba pyttsx3 para hablar.

En Windows pyttsx3 funciona bien porque usa la voz de Windows, pero en Mac se
me quedaba mudo o no terminaba de hablar bien algunas frases.

Entonces revise como podia hacer hablar a la Mac desde terminal y encontre que
macOS tiene un comando nativo que se llama:

"SAY"

Por ejemplo en terminal se puede ejecutar:

say "Hola, esta es una prueba"

Y la Mac habla directamente.

Por eso se modifico voz_tts.py para que si Python detecta que esta en macOS,
use el comando nativo say. La condición que se usa es:

Este es el archivo que cambié estaba algo asi 

self._pyttsx3.say(texto)
self._pyttsx3.runAndWait() 

y se cambio por una instrucción de Mac que me pareció más fácil 

subprocess.run(["say", texto], check=True)

Se le agrego un IF
Para determinar que si era una MAC en el entorno que estaba corriendo 

if sys.platform == "darwin":  #aqui es donde comparo si es una MAC darwin regresa el valor si es una macOs 

Claro que para llegar aquí si tuve que buscar mucho y si le pregunte a la IA como podia determinar
Que si no era windows se fuera por aqui y a esto se llego en esta parte del archivo 


Seleccion del microfono

También tuve que revisar como seleccionar el micrófono correcto.
En config.py esta esta variable:

MIC_DEVICE_INDEX_OVERRIDE

Ahi se pone el numero del micrófono que se quiere usar. En mi caso use el indice
3 porque era el que detectaba mi micrófono USB de mi webcam.

Para listar los micrófonos use un comando de Python con speech_recognition,
que muestra todos los dispositivos de entrada disponibles.

Adaptación para Mac

Otra cosa que cambie fue la parte de abrir aplicaciones.
El proyecto venia mas para Windows, por ejemplo notepad. En Mac no existe
notepad, entonces lo adapte para abrir Notas, Chrome y Terminal.

En Mac se usa el comando open para abrir aplicaciones, por eso en acciones.py
se uso algo como:

subprocess.Popen(["open", str(ruta)], shell=False)

Tambien se ajustaron rutas en config.py para que apuntaran a aplicaciones de
macOS.

Entendiendo como agregar comandos

Después de revisar varios días entendí que para agregar un comando nuevo casi
siempre se tocan estos archivos:

1. config.py
Aqui se agrega el verbo a la lista VERBOS.

2. gramatica.py
Aqui se agrega el verbo a la gramatica y si es necesario se agrega a
VERBOS_CON_OBJETO_ABIERTO para que acepte frases largas después del verbo.

3. acciones.py
Aquí se programa la función que realmente hace el trabajo.

4. agente.py
Aquí se conecta el comando de voz con la función.

Por ejemplo si digo:

jarvis dame el tipo de cambio

El flujo mas o menos es:

voz_stt.py escucha y convierte a texto
agente.py recibe el texto
gramatica.py valida que la frase este bien
agente.py este es el mero mero aqui recibo la voz la separa en palabras detecta la 
          palabra de acción "JARVIS" y el verbo y decide que función utilizar y hasta 
          la voz aqui se manda llamar 

acciones.py aqui se ejecuta el comando por ejemplo "consulta Banxico"
voz_tts.py responde hablando


Comando 1: Tipo de cambio de Banxico

Para el primer comando nuevo recorde que en un ERP que estoy haciendo por coding
ya habia usado una API de Banxico para consultar el tipo de cambio.

Por eso se me hizo buena idea integrar ese mismo concepto al asistente.

El comando quedo:

jarvis dime el tipo de cambio
jarvis dame el tipo de cambio

Primero agregue los verbos dime y dame en config.py.
Luego los agregue tambien en gramatica.py.

En acciones.py agregue una funcion para consultar Banxico.
Se agregaron los imports:

import json
import urllib.request

La API de Banxico que se usa es:

https://www.banxico.org.mx/SieAPIRest/service/v1/series/SF43718,SF343410/datos/oportuno

Esa consulta trae el tipo de cambio FIX y el tipo de cambio de cierre.

En agente.py se agrego una condicion para que si la consulta contiene palabras
como tipo de cambio, dolar o cambio, entonces mande llamar la funcion de Banxico.

Este fue el primer comando terminado:

JARVIS DAME/DIME EL TIPO DE CAMBIO


Comando 2: IP publica

Después pensé en un comando sencillo pero util, que fuera consultar mi IP
publica.

El comando quedo:

jarvis dame mi ip publica
jarvis dime mi ip publica

Para esto use una API muy sencilla:

https://api.ipify.org

Esa pagina lo único que devuelve es la IP publica de la conexión.

En acciones.py agregue una función que abre esa URL, lee el texto y guarda la IP
en una variable.

Luego para que se escuche mejor, cambie los puntos por la palabra "punto".
Por ejemplo:

189.203.44.12

se convierte en:

189 punto 203 punto 44 punto 12

En agente.py agregue una condición para que si la consulta contiene la palabra
"ip", entonces ejecute la función de IP publica.

Con esto quedo listo:

JARVIS DAME MI IP PUBLICA


Comando 3: Ciudad y clima

Para el tercer comando quise hacer algo que se viera mas completo.
La idea fue que el asistente pudiera decirme en que ciudad estoy y tambien darme
el clima de esa ciudad.

Los comandos quedaron:

jarvis donde estoy
jarvis dime el clima
jarvis dame el clima
jarvis dame la temperatura

Para esto se usan dos servicios públicos:

1. API para detectar ciudad:

http://ip-api.com/json/

Esta API revisa la IP publica desde donde se hace la consulta y regresa datos
como pais, region y ciudad.

2. API para consultar el clima:

http://wttr.in/

El flujo fue:

primero consulto ip-api.com
guardo la ciudad en una variable
luego uso esa ciudad para armar la URL de wttr.in
consulto el clima
guardo el resultado en otra variable
armo una frase final
el asistente la dice por voz

La URL del clima queda parecida a esto:

http://wttr.in/Mexicali?lang=es&format=%C+con+temperatura+de+%t

lang=es es para que responda en español.
%C es la condición del clima, por ejemplo Soleado.
%t es la temperatura.

Me paso que con https me daba un error de seguridad o certificado en mi Mac,
entonces lo deje con http y funciono sin problema para esta consulta publica.

También deje Mexicali como valor de respaldo por si algún día no detecta la
ciudad, porque es donde estoy trabajando y así no se rompe la demostración.

Para que funcionara "jarvis donde estoy" tuve que agregar el verbo donde en:

config.py
gramatica.py
agente.py

En agente.py se agrego que si el verbo es donde, ejecute directamente la función
del clima local.

Con eso el asistente responde algo como:

Según tu dirección de internet, estas en la ciudad de Mexicali. El clima actual
es Soleado con temperatura de +29°C.


Palabras de activación

También agregue jarvis y jarviz como palabras de activación.
La razón es que a veces Google entiende diferente la pronunciación, entonces si
digo Jarvis puede transcribir jarviz. Por eso deje las dos para que el asistente
responda mejor.

- Algunas aplicaciones eran de Windows y se adaptaron a Mac.
- Para tipo de cambio primero funcionaba con dime y luego agregue dame.
- Para donde estoy tuve que agregar donde como verbo en config y gramática.
